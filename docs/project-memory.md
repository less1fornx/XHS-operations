## 业务目标

- 为小红书个人号构建西装定制店 B2B 运营工作台。
- 优先筛选活跃、客单价中高档的西装定制店，根据店铺当前公开内容生成评论或私信草稿。
- 我方是可以做高端品质的毛衫（针织衫）加工工厂，向西装定制店供应西装内搭，款式不限。内搭是西装定制店（实体店）的附加业务：客人订西装时顺带搭配；不是让对方开拓针织业务或建立针织供应链。（2026-10-03 用户纠正定位）
- 区别于其他工厂的核心优势是支持“一件起订”，并且产品细节和质量经得起推敲。（2026-10-02 用户确认，替换此前“服装和西装店内搭”的笼统表述）
- 针对西装定制店的促单要点：对方只需留一件样衣，不存在存货压力；有订单时直接联系我方下单，一件也可以做。
- 懂纱线的人也会主动联系了解产品，因此主动来询的对象不限于西装定制店。
- 首次私信中最吸引目标人群的三点（2026-10-02 用户确认）：我们是工厂并且接受一件起订；累计已承接过约 200 家不同西装定制店的业务；品质有保障。
- 不免费寄样衣。对方有意向时，可按成本价购买一件，由我方邮寄。（2026-10-02 用户确认）
- “累计约 200 家西装定制店”这一数字经用户确认准确。
- “多少年生产经验”不放在首次私信中，用户判断对方多数不会相信；等对方有意向后再作为事实说明。
- 私信内容必须针对被联系账号的主体定制，根据对方是什么样的店、发什么内容来写，不能套用统一模板。
- 陌生店铺 DM 是主要业务场景。目标对象是店铺经营者，目的是询问其是否有采购我方产品的需求，不是截取其他店铺评论区中的顾客。
- 私信必须结合目标店铺的账号内容、具体视频或业务场景生成，不能只替换店铺名称形成群发模板。
- 本系统负责业务最关键的前期获客工作：选择后续跟进对象、判断对方是否可能愿意了解产品，并辅助完成首次沟通。
- 用户后续会补充我方产品优势，并在发送私信的账号上发布面向 B 端需求、产品能力和品牌思想的内容，作为后续促单的信任基础。
- Agent 负责证据整理、评分、路线建议和内容起草；人工负责路线确认、最终文案审核和小红书官方页面发送。
- 系统需要形成持续运营学习闭环：人工记录店铺的回复、意向、成交和未成交结果；系统定期比较成交与未成交店铺的特征，提出店铺筛选和首次沟通优化建议。

## 固定运营边界

- 每日内部上限为 5 家私信、3 家评论，同一店铺同一天不能同时进入两种触达路线。
- 不自动登录、批量抓取、自动发送、自动追发、换号重试或绕过平台限制。
- 陌生店铺 B2B DM 不能被旧规则直接拒绝，但仍必须经过人工审核并由人工在小红书官方页面发送。
- “一件起订”是可用于个性化 B2B DM 的真实业务事实，不作为全局硬拦截词。
- 私信已发送且人工确认已读无回复后，店铺进入勿扰名单，不再参与后续评选。
- 对方主动索要电话或微信、或发来二维码时，系统不生成回复，转入人工商务阶段，由人工处理。（2026-10-02 用户确认，现阶段做法）
- Agent 不能根据单个成交案例自动修改评分、筛选规则或 Prompt。所有优化先形成带样本量和证据的候选建议，经人工批准、小范围验证和版本记录后才能生效。

## 当前技术决策

- Python 固定为 3.12.14，Node 固定为 24.21.0。
- Phase 0、Phase 1A、Phase 1B、Phase 1C、Phase 1D 已完成。
- Phase 2 主模型选择国内 Qwen API；未来本地文本/理解模型沿用 Qwen 系，图像和视频生成使用独立 Provider 路由。
- Phase 2A 已完成：结构化输入/输出、版本化 Prompt、Qwen/Mock Provider、证据引用校验和固定案例评测均已落地；生产工作流接入属于 Phase 2B。
- 业务规则、配额、状态机和发送权限由代码控制，不能交给 LLM 自由决定。

## Phase 2 学习与评估要求

- 用户需要参与业务规则、Prompt、上下文、结构化输出和评估集设计，而不是只提供 API Key。
- 第一批评估集使用脱敏的真实或拟真案例，覆盖 DM、评论和拒绝路线。
- 评估案例必须保留对象身份字段，业务判断字段本身不能代替完整案例记录。
- 身份字段至少包括：`case_id`、`shop_name`、`xhs_account`；`profile_url` 可选。
- 生产数据与评估数据分开保存。评估数据可脱敏，但同一案例内必须能稳定识别同一家店铺和对应证据。
- 每次模型调用需要保存模型版本、Prompt 版本、输入证据 ID、结构化输出、人工修改和最终决策。

## 持续优化闭环

- 前端需要为每家已触达店铺提供“结果与成交反馈”人工入口，至少记录：回复状态、意向阶段、是否成交、成交时间、实际需求、主要吸引点、主要异议和人工备注。
- 不能只记录成交案例。已读未回、明确拒绝、回复但无意向、进入报价但未成交等负样本同样必须保存，否则特征分析会产生幸存者偏差。
- 分析必须使用“联系当时”的店铺特征和文案版本快照，避免把成交后才知道的信息泄漏进筛选模型。
- 周期分析先计算可解释指标，再由 LLM 总结规律：不同店铺类型、内容主题、采购信号、个性化依据和文案版本对应的回复率、正向意向率与成交率。
- 样本不足时只能输出“观察”或“假设”，不能直接称为规律。第一版默认每周生成一次草案；累计触达少于 20 家或成交少于 3 家时，不允许自动提出正式策略替换。
- 每项优化建议必须包含适用人群、样本量、正负样本对比、预期影响、风险、建议修改内容和回滚条件。
- 人工批准后生成新的筛选策略版本或 Prompt 版本；旧版本保留，可对照评估和回滚。
- 策略优化只改变候选排序、建议路线和文案生成，不改变人工审核、每日配额、勿扰名单和人工发送边界。

- 新增 `target_role`、`contact_mode`、`outreach_purpose`、`agent_suggested_route`、`expected_route`、`risk_level`、`human_decision` 等字段和枚举。

- 将陌生 B2B DM 固定定义为 `high` 风险。
- 右栏给出的 Qwen JSON 输出结构、评分数值、示例店铺和示例文案。

平台是否允许、限制或处罚特定陌生 B2B 私信，属于需要依据官方规则持续核实的外部约束，不能仅根据右栏助手的判断直接写成产品需求。

## Phase 2C 截图录入与初筛（2026-10-03 用户确认）

- 系统在发私信之前对店铺做初步判断：哪一家成功可能性大、对这家写什么内容成功可能性大。
- 判断规则 v0 暂定为 `docs/phase2c-screenshot-intake-design.md` 中的草案（前提：主营西装定制；信号：活跃、注重面料、高客单价、实体门店；高档至少两项且含面料或客单价）。
- 每批最多 10 家店，每家最多 3 张截图。截图原图只存本机，保存 10 天后删除，系统长期只保存提取出的文字。
- 成功标准第一版：用户对分档和草稿做互动标注；用户标注（偏好）与对方回复（结果）分开保存。

## 发送后的结果记录（2026-10-03 用户确认）

- 当前项目重心是获客渠道：详细记录第一次回复，之后只更新进展阶段，不逐条记录后续沟通。
- 记录三类内容并分开保存：事实（是否回复、回复时间、对方原话）；对方想要什么（固定标签，可多选，只按对方原话选）；进展阶段（人工判断，单选）。“是否想了解产品”由标签推出，不单独存。
- 回复时效：发送后 3 天内回复为正常回复；3 到 15 天为迟回复，分析时作为次要样本；15 天没有回复，系统自动结束任务并标为未回复。
- 进展阶段：未回复、已回复但无意向、想了解产品、要买样衣（成本价一件）、谈报价、成交、未成交。“对方拿一件样衣，有订单再找我们下单”是当前真实存在的合作模式。
- 每次确认发送时保存“联系时快照”：当时的分档、信号、切入点、规则版本、Prompt 版本和最终发出的文案，之后不再修改。
- 私信截图只在内存中读取，不保存；电话、微信等联系方式不进入数据库。

## 账号识别与文案修改（2026-10-03 用户确认）

- 小红书号是识别一家店的唯一依据。店名会重复、会改；双方都有小红书号时只按小红书号判断是否同一家，没有小红书号时才退回按店名或主页地址判断。
- 发送时按小红书号搜索目标账号，不按店名搜索。
- 是否联系过、勿扰名单、批内去重都以小红书号为准。
- 人工可以修改文案，包括审核通过之后、发送之前。系统必须记录改了哪些部分，并保存修改原因，用于以后改进草稿。

## 当前优先级

先完成私信业务的 Qwen 结构化生成、人工审核和评估闭环；图片理解随后接入，图片生成和视频生成不进入当前 Phase 2 主链路。

真实成交反馈当前不可用，不阻塞 Phase 2。系统已预留结果反馈数据契约和批量导入 API；待用户未来提供数据后再启用真实周期分析。

## 现阶段重点（用户 2026-10-05 确认）

- 是否匹配的判断目前比较模糊，现阶段重点是后续的文案生成；前期匹配规则要根据后续使用结果再优化。
- 批量初筛里读取失败的店，应在同一批次内重试或换图，不应要求重新建批次、重复上传。
- 读图结果缺少字段时，按空值记录并提示核对，不因此判为失败。
- 分档规则和字段的调整，由 Claude 根据已提交的数据提出修改建议，用户确认后实施。
