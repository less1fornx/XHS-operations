## 9. 你的成长路线：FDE

FDE（Forward Deployed Engineer，前线部署工程师）的工作是：进到客户的业务现场，弄清真实问题，用现有技术快速做出能用的系统，再用数据证明它有用并持续改进。写代码只是其中一部分，更重的是**把模糊的业务问题变成可检验的系统**。

你的优势是：你自己就是业务方，懂毛衫、懂西装定制店、有真实客户。缺的是把业务判断转成系统设计的方法。这个项目正好练这个。

| FDE 能力 | 含义 | 在本项目里怎么练 | 你的现状 |
|---|---|---|---|
| 问题拆解 | 把“帮我获客”拆成可以分别解决的小问题 | 读店、分档、起草、发送、回复，各自的输入输出是什么 | 已做过：你提出了“先判断哪家成功率高，再判断发什么” |
| 定义“好” | 给每个环节定可检验的标准 | 第 3 节的完成标准由你定 | **现在要练的** |
| 判断分工 | 哪些交给模型、哪些写成规则、哪些必须人来 | 理解为什么分档用规则而不用模型 | 见过，还没亲手设计 |
| 数据设计 | 为了以后能评估，现在该存什么 | 回复记录的字段和标签是你设计的 | 已做过一次 |
| 评测驱动 | 先有考卷，再改系统，用分数说话 | 下一步第 5、6 项 | 未开始 |
| Prompt 与上下文 | 模型该看到什么、该怎么被要求 | 阶段三亲手改一条规则、增减一类信息 | 未开始 |
| 编排 | 步骤、并行、暂停、失败处理 | 阶段三设计一个流程改动，读 LangGraph 代码 | 未开始 |
| 排查 | 出问题时定位是数据、Prompt、规则还是代码 | 看 `model_invocations` 里模型实际收到和返回了什么 | 未开始 |
