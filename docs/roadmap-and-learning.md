## 现在在哪

一个 Agent 应用可以分成五层。前四层已经搭好并跑通，第五层几乎是空的。

| 层 | 作用 | 本项目现状 | 代码位置 |
|---|---|---|---|
| 1 业务建模 | 把生意变成规则和数据结构 | 已有：产品事实 v2、分档规则 v0、店铺类型、勿扰规则 | `config/product_facts.v2.json`、`packages/agent_core/screening.py`、`contracts.py` |
| 2 上下文 | 决定模型能看到什么 | 已有：截图摘抄、证据编号、产品事实注入 | `services/worker/lead_generation.py`、`packages/agent_core/vision.py` |
| 3 Prompt 与契约 | 告诉模型怎么做、输出什么格式 | 已有：起草 Prompt v4、读图 Prompt v1、输出校验 | `prompts/`、`contracts.py` |
| 4 编排与护栏 | 步骤顺序、并行、人工停点、失败处理 | 已有：单店流程、批量流程、勿扰拦截、策略检查、超时结束 | `labs/phase0-langgraph/.../lead_workflow.py`、`services/worker/screening_graph.py` |
| 5 评估与迭代 | 知道好不好，并据此改进 | **缺**：结果只记到“已发送”；标注散落在批次里；考卷只有 6 题；没有分析 | `evals/`、`packages/agent_core/evaluation.py` |

数据层的具体缺口：

- 表已经有（`outreach_outcomes`，含回复、意向、成交和三类标签），但没有录入界面，目前 0 条。
- 没有保存“联系当时”的快照：当时的分档、命中的信号、切入点、规则版本、Prompt 版本、最终发出的文案。
- 分档的“同意/不同意”和读图改正只存在批次记录里，没有汇总。
- 草稿没有标注入口（好、一般、不好和原因）。
- 没有周期分析，也没有“规则或 Prompt 改版前后对比”的流程。

## 后续安排

每一步都分成“你做什么”和“我做什么”。设计由你做，我提问、指出漏洞、实现，并在代码里标出对应你的哪条决定。

### 第 0 步：用真实店铺跑起来（不写代码）

- 你：每天用批量初筛跑一批真实店铺，标注分档，改草稿，真实发送几家。
- 目的：没有真实数据，后面每一步都是空转。也只有用过，你才知道哪里别扭。

### 第 1 步：结果记录与联系时快照（数据层）

- 学什么：Agent 应用的数据要为“以后评估”而存；为什么必须存当时的快照而不是事后的状态。
- 你设计：一次回复要记哪些字段；“对方问了什么”的固定标签有哪些（起点可用 18 个样本里出现过的：要资料、要价格、要款式、问定制、问代发、转交同事）。
- 我实现：发送时自动存快照；前端加“记录回复”窗口。

### 第 2 步：标注汇总与第一个指标

- 学什么：怎么定义“好”；偏好数据和结果数据为什么要分开。
- 你设计：草稿“不好”的原因选项；一致率怎么算才公平。
- 我实现：草稿标注入口；汇总页（分档一致率、草稿通过率、人工修改幅度）。

### 第 3 步：用真实数据扩充考卷

- 学什么：评测集怎么来；什么是回归测试；为什么改 Prompt 前要先有考卷。
- 你做：从真实跑过的店里挑 10 到 15 个有代表性的，定下每个的预期。
- 我实现：把它们转成固定案例；补上“禁止编造承诺”这类检查。

### 第 4 步：亲手做一轮 Prompt 迭代（学习重点）

- 学什么：Prompt 工程的基本循环：看失败案例 → 找原因 → 改一条规则 → 重跑考卷 → 对比。
- 你做：选一个你最不满意的草稿问题，自己改 Prompt 文件里的一条规则。
- 我做：跑评测，给你看改前改后的对比，解释为什么有效或无效。

### 第 5 步：亲手改一次上下文（学习重点）

- 学什么：上下文工程。同一个 Prompt，喂给模型的信息不同，结果差别有多大。
- 你做：决定加一类信息或减一类信息（例如加入“这家店的切入点”或去掉某类证据），预测结果会怎样。
- 我做：做成可切换的两个版本，跑同一批案例对比。

### 第 6 步：亲手改一次编排（学习重点）

- 学什么：LangGraph 的节点、状态、分支、暂停和恢复。
- 你做：设计一个小改动，例如“读图发现信息不足时，暂停并让你补截图，再继续”。先画流程，我指出漏洞。
- 我做：实现，并带你逐行读这段图的代码。

### 第 7 步：周期分析与策略版本

- 学什么：怎样让系统持续改进而不失控：样本量门槛、人工批准、版本记录、回滚。
- 前提：累计联系 20 家以上。
- 做法：程序先算数字，模型再写结论并标注样本量；你批准后才生成新版规则或 Prompt。
