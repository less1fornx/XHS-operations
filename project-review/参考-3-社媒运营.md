# 参考 3：社媒运营

- 项目：[langchain-ai/social-media-agent](https://github.com/langchain-ai/social-media-agent)
- 读的版本：2026-10-01，提交 `586e436`
- 规模：250 多个文件，TypeScript

## 它做什么

给它一个网址，它读内容、写一份分析、起草推特和领英的帖子、配图，交给人审核，通过后按排期发布。LangChain 自己的官方账号在用它。

三个项目里它最接近“运营工作台”，结构也最完整。语言是 TypeScript，和我们的后台不同，所以看的是组织方式，不是具体代码。

## 目录怎么放

这是它最值得对照的地方。

```text
src/agents/
├── generate-post/            一个流程一个目录
│   ├── generate-post-graph.ts    流程图本身
│   ├── nodes/                    每个步骤一个文件
│   └── prompts/                  这个流程的 Prompt
├── reflection/               从反馈里更新规则
├── curate-data/
│   ├── nodes/tweets/tests/       测试放在被测的东西旁边
│   └── loaders/tests/
├── shared/                   多个流程共用的
│   ├── nodes/generate-post/human-node.ts   人工审核节点，几个流程共用
│   └── stores/                             共用的存储
scripts/                      运维脚本：建定时任务、查排期、补跑
.github/workflows/            三条自动检查
```

共 14 个流程，各自独立，名字和入口登记在一个文件里（`langgraph.json`）。

对照我们：主流程在 `labs/phase0-langgraph/` 下，接口和业务逻辑挤在一个一千多行的文件里，测试全在 `tests/`。

## 一条帖子的流程

`src/agents/generate-post/generate-post-graph.ts`：

```text
核对链接 → 写分析报告 → 起草帖子 ─┬─ 超过 280 字 → 压缩（最多 3 次）─┐
                                └─ 没超 ───────────────────────────┴→ 配图 → 人工审核
人工审核 ─┬─ 接受或修改 → 排期发布
          ├─ 写一句指示 → 重写，或改排期 → 回到人工审核
          └─ 忽略 → 结束
```

两处值得注意：

**自动检查不过就自动重写。** 帖子太长时不直接交给人，先让模型压缩，最多 3 次。人看到的已经是过了基本检查的版本。

**人写的一句话会被分流。** 人回一句话，系统先判断这是“要改内容”还是“要改时间”，再走不同的步骤。

## 人工审核节点

`src/agents/shared/nodes/generate-post/human-node.ts`。四种回应：

| 回应 | 结果 |
|---|---|
| 接受 | 按排期发布 |
| 修改后提交 | 用改后的版本发布 |
| 写一句话 | 按这句话重写，或调整排期 |
| 忽略 | 不发，流程结束 |

排期可以写具体时间，也可以只写优先级（p1、p2、p3），系统自己找下一个空档。

## 从反馈里更新规则

`src/agents/reflection/index.ts`。人对一条帖子给了反馈后，一个单独的“反思”流程判断要不要更新写作规则。它的原则写得很清楚：

- 只有反馈是明确的，并且能推广到以后所有帖子时，才更新。
- 不从含糊的反馈里推断规则。
- 不过度推广。
- 新规则和旧规则冲突时，用新的。

## Prompt 怎么组织

`src/agents/generate-post/prompts/`。一个完整的 Prompt 由四块拼成，每块单独存放：

| 块 | 内容 |
|---|---|
| 业务背景 | 我们是谁，关心什么 |
| 好例子 | 129 行真实发过的帖子（`examples.ts`） |
| 结构要求 | 帖子分几段，每段写什么 |
| 内容规则 | 能写什么，不能写什么 |

想换一套风格，只换其中一块。

## 工程上的东西

- **31 个测试文件**，和被测的代码放在一起。
- **三条自动检查**（`.github/workflows/`）：格式和代码规范、单元测试、集成测试。每次提交自动跑。
- **去重库**（`src/agents/shared/stores/post-subject-urls.ts`）：记下用过的链接，同一个内容不发第二次。作用相当于我们用小红书号防止重复联系。
- **运维脚本**（`scripts/`）：创建定时任务、列出已排期的帖子、补跑漏掉的。
